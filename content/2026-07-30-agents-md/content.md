## 200 行的 AGENTS.md，把 Agent 喂笨了

我的 AGENTS.md 从 20 行养到了 200 行。

每次 Agent 犯错，我就加一条规则。加到后来，它开始漏步骤、忽略约定、明明写了却当没看见。

规则越多，它越不听话。

<!-- era:page-break -->

## 为什么规则越多反而越差

- 挤占注意力：200 行无关规则每次都进上下文，真正相关的那 3 行被淹没
- 互相打架：「复用现有组件」和「保持单一职责」在同一个任务里会冲突，模型只能随机挑一条
- 中段失忆：长文本里模型对开头结尾记得最牢，中间命中率最低

<!-- era:page-break -->

## 第一步：主文件只留硬约束

「每个任务都必须遵守」的才留下，20 行封顶。

判断标准：这条规则在写 CSS 时也成立吗？不成立就搬走。

## 第二步：其余按场景拆成独立文件

测试规范、发布流程、组件约定各自成文，放进 .rules/ 目录。

Agent 需要时才读，不需要就不进上下文。

<!-- era:page-break -->

## 第三步：主文件只写路由

主文件回答一个问题就够了：什么情况下去读哪个文件。

```
改 UI 前   → 读 .rules/ui.md
发版前     → 读 .rules/release.md
写测试前   → 读 .rules/test.md
```

<!-- era:page-break -->

## 什么情况下不该删

- 安全约束：不许提交密钥、不许直接改生产库
- 团队硬规范：分支命名、提交格式
- 破坏性操作红线

这类必须常驻，删错的代价比降智大得多。
