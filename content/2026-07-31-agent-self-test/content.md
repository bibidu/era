## 每次都得我说「跑一下测试」

Agent 改完代码就交活，测试它一次都不碰。

我自己跑，红了再把报错贴回去，它再改。一天下来这句话我要说十几遍。

后来我在 .rules/test.md 里加了 3 行，它自己就跑了。

你的 Agent 现在会自己跑测试吗？会 / 不会，评论区回一个字

<!-- era:page-break -->

## 它不是懒，是缺了三样东西

- 没有「改完了」的定义：代码生成完，任务在它那里就结束了
- 不确定该跑哪条命令：npm test 还是 vitest 还是 pytest，猜错一次就不再试
- 没有失败后的剧本：跑红了不知道该修还是该问，于是干脆不跑

<!-- era:page-break -->

## 我加的 3 行

```
改完 src/ 下任何文件后，执行 npm test -- --run
失败：只看第一条报错，修完重跑，最多 3 轮
3 轮仍红：停下，把失败用例名和报错原文贴给我
```

<!-- era:page-break -->

## 3 行为什么够用

- 第 1 行把「改完」变成能判定的条件，命令写死，不留猜的空间
- 第 2 行给失败一个剧本，一次只修一条，不让它一口气乱改五处
- 第 3 行是刹车，防止它为了让测试变绿去删断言、改期望值

<!-- era:page-break -->

## 什么情况会失效

- 全量跑超两分钟：命令后加文件路径，只跑相关用例
- 命令要 sudo 或要连数据库：它会卡住，先给一个本地能跑的最小集
- 无网环境：先标出需要联网的用例，否则它会当成代码错了一直改
