# 风水竖版成片（一个链接 → 9:16 口播视频）

**本 skill 只做出片，不做 Era 多页图文。** 阳宅图文、gc-minimal-zine-poster 底图、分篇叠字、`image_previews` 多页入库流程**全部废弃**；若对话里还出现旧说法，纠正并改走本流程。

用户给**一个抖音链接（或等价视频链接）**即可启动：抽口播 → 改词 → 选择本机克隆引擎 → 10 秒真实克隆与首帧 → **用户确认** → 全片逐字/音质门禁 → 山水静图 → 片头毛笔标题+锦垣印 → 宋体字幕 → 拼 1080×1920 成片 → 交付 HTTPS 预览链接。

## 强制确认阶段

- 先用最终选定的克隆引擎、`public/audio/150-20s.wav` 和本篇真实文案生成约 **10 秒真实克隆音频**；禁止用参考音、旧样片、设计音色或其他 TTS 冒充。
- 同时生成**最终首帧截图**：本篇山水底图 + 本篇 AI 毛笔标题 + 锦垣印 + 首句字幕，版式必须与正式成片一致。
- 10 秒音频先通过下述逐字与音质门禁，再与首帧放入绑定本次素材的 HTTPS 确认页，请用户确认：声线、发音、语速、毛笔笔形、字号、位置与印章关系。
- **只有用户明确确认后**才能生成剩余音频和正式成片。用户说「不用确认 / 直接出 / 全自动」也不能跳过；被 **风大师**（`fengdashi`）调用时同样在此暂停，选题/标题/档期仍保持自动决策。

## 主流程

### 1. 抽口播 + 改词

1. 从链接抽出**中文口播文案**（听写/字幕/旁白均可，以可念的中文为准）。
2. **改词少于 5%**：只允许换词或微调句序，**含义不变**；不要大段重写、不要加戏。
3. 读音（口播注入；上游亦可参见 `bibidu/bbd5213` 的 `docs/voice-reading.md`，仓内副本见 [references/voice-reading.md](./references/voice-reading.md)）：
   - **Qwen** → 读「千问」
   - **Codex** → 读 `/ˈkoʊ.dɛks/`
4. 输出定稿口播稿（纯中文可读文本），供配音与字幕共用。

#### 1.1 首帧选题与标题

1. 标题文案与标题生图是两个任务：先由 **3 个独立文本模型并行提案**（默认 GPT-5.6 Terra High；用户另指定模型时从其要求），再由主代理按原口播、悬念和版式综合选择；GPT 图像模型只负责绘制已定文字，**不得**让生图模型自行选题。
2. 标题必须忠实原口播、语法自然，并优先保留答案悬念；不要把口播里的两个结果全部提前写在封面上。禁止为凑短句制造「欠款还」一类生硬压缩表达。
3. 每个提案必须给出：选题、右列、左列、合读、原文映射与风险。主代理只能选逐字可追溯到原文、没有新增时限/因果/财富承诺的一案。
4. 2026-09-04 本篇当前确认稿示例：原文「在你身上将有两件事情发生」→ 右列「两件好事」、左列「要发生」，合读「两件好事要发生」；「好事」来自后续贵人/还款两个正向结果，不提前剧透具体答案。它是本篇候选，不得硬编码为其他视频标题。

### 2. 配音（本机克隆引擎 · 老者）

#### 2.1 引擎选择

固定优先级：**CosyVoice > VoxCPM2 > VoxCPM 0.5**。

1. 依次探测本机已安装且能读取模型的环境；若装有多个，只选优先级最高者。
2. 若三者均未安装，先做 [本机运行](./references/local-runtime.md) 的资源预检；按上述顺序选择机器能安全加载、完成 10 秒样本且不会 OOM / swap 抖动的第一个引擎，在独立环境安装其最新兼容稳定版与模型。
3. 当前引擎连续两次不能通过逐字/音质门禁，停止使用它，按顺序尝试下一个已安装或机器可安全运行的引擎；每次切换都重新生成 10 秒样本并让用户确认。
4. 记录最终引擎名称、版本、模型标识和运行设备；禁止把 VoxCPM2 写成 VoxCPM 0.5，或把任意设计音色写成真实克隆。
5. **禁止 MiniMax**。

#### 2.2 老者参考

- 固定参考音：仓内 `public/audio/150-20s.wav`。
- 固定参考文本：[本机运行](./references/local-runtime.md) 中的精确文本；必须先确认音频内容与文本逐字对应，再成对传入引擎。
- 原 fengshui-B / MiniMax B 轨只是一份已转换来源，**不要**回落到 MiniMax。
- 同一时刻只允许一个本机重负载阶段：安装、合成、ASR、OCR、嵌入、FFmpeg/Remotion 或 Blender 不得并行。预检不通过时不要暂停其他任务，只报告等待条件。

#### 2.3 逐字与音质门禁（10 秒样本和全片都必须通过）

1. **逐字**：按句切分后用独立中文 ASR + 字级时间戳回读；忽略标点后，识别文本必须与目标中文逐字一致，不能缺字、错字、多字、换序或变成其他语言。输出逐字 diff；有一字不一致即失败。
2. **停顿**：句首/句尾静音各不超过 300ms；非标点处停顿不超过 350ms；普通标点处不超过 650ms；任何超过 1 秒的内部静音直接失败。
3. **纯净度**：无爆音、削波、点击、底噪突变、重复音节、吞字、机械颤音和非中文幻觉音节；削波样本占比不高于 0.01%，信噪比至少 25dB。
4. **响度**：综合响度控制在 -20 至 -14 LUFS，True Peak 不高于 -1dBTP；不能靠后期暴力增益掩盖异常低音量。
5. **异常低音**：同时检查音量与基频。基频中位数应与参考音同量级（建议参考的 0.75–1.25 倍），不得持续低于 65Hz；60Hz 以下异常能量、工频嗡声或低频轰鸣需清理后重验。
6. **语速/完整性**：逐字时间戳连续，不能提前 EOS；中文平均语速建议 3–5 字/秒。生成进度异常提前结束、目标文本覆盖不足或语言识别非中文，直接失败。
7. 门禁失败时不得进入视频合成，也不得用“文件可解码 / 有 AAC 音轨 / 时长存在”冒充通过。

### 3. 静图（山水 · 9:16）

- 风格：**cinematic 9:16 shanshui + anime**。
- 人物：1–2 个行者/旅人，**小但能看清**；风景为主体。
- **上三分之一留空**给片头标题（构图勿把主景顶满）。
- 若生图是横图：对**整幅**做竖裁到 **1080×1920**；**禁止**上下拼接，**禁止**补天补地。
- 成片全程该图**静止**（Ken Burns / 推拉摇移一律不要）。

### 4. 片头：毛笔标题 + 锦垣印（停留 2 秒后消失）

时间轴：

| 时段 | 画面 |
| --- | --- |
| 0–2s | 静图 + 毛笔标题 + 锦垣印 |
| 2s 之后 | **只留**静图 + 字幕（标题与印消失） |

标题：

- **AI 毛笔**（白飞白行楷），**右起左行两列竖排**
- 生成前必须读取固定多参考集 [`public/fengshui-assets/calligraphy-references/`](../../../public/fengshui-assets/calligraphy-references/) 及其 `manifest.json`：三张完整首帧与三张对应毛笔字局部必须**成组输入同一次图像生成上下文**
- 完整首帧只负责约束标题在 9:16 画面中的字号、位置、双列节奏和印章关系；对应局部只负责约束笔锋、飞白、字重、起收笔和单字字面。禁止拿局部裁图边界当最终布局，也禁止只挑单张参考照抄
- 三组共同风格为：偏行楷的手写毛笔、粗细反差明显、露锋起笔与长锋收笔并存、转折有墨块、笔画内部保留自然飞白和干笔分叉；不能变成电脑行楷、等粗描边、圆头笔刷或平滑矢量字
- 每篇标题仍须依该参考**重新生成对应文字**；禁止裁用示例中的字、复用示例文案，或用代码/UI 字体替代
- 新标题必须使用**简体中文**；图像生成后逐字 OCR 并人工目视核对。任何错字、缺字、多字、异体字或繁简混用都必须重生成，不能靠解释放行
- 禁止马善政、系统黑体、数黑体等代码/UI 字体冒充毛笔
- 完整参考集的基础范围是画宽 `22.5%–75.6%`、画高 `17.3%–59.1%`；用户已明确偏好更大的榜书字面。**4+3 字标题默认采用放大验收范围**：1080×1920 下整体可见墨迹约 `x=190–865, y=285–1130`，四字列宽约 `260–280px`、三字列宽约 `285–305px`，标题块高约 `840px`。此前单列约 `220px` 的版本判定为过小，不再复用
- 4+3 放大布局列心参考：左列约 `x=340`、右列约 `x=730`，净列距约 `100–125px`；四字列单字视觉高度约画高 `8%–11%`。字距可随笔势小幅变化，禁止 UI 字体式机械等距
- 两列字数不同时，以最长列确定总高，较短列在最长列高度内**垂直居中**；按单字尺度重排，禁止把不同字数强拉到同一总高度
- 两列必须使用同一等比缩放因子，保留不同汉字天然宽窄；只允许按 alpha 包围盒等比缩放，不得分别横纵拉伸
- 首选直接生成白色笔核 + 半透明飞白的 **RGBA**。若 GPT 图像模型不能输出真透明，只允许生成**纯黑、均匀、无纹理**的软蒙版底（暗区均值与标准差均应 `<1`），再按连续亮度计算 alpha，例如 `α=clamp((L-3)×255/252)`；这是灰度软蒙版，不是硬 `colorkey`。必须拒绝画进 RGB 的棋盘格、渐变底、纹理底和阈值硬抠，避免破坏笔丝
- 首帧验收必须同时对照完整封面的归一化位置和局部裁图的笔形；只满足其一仍算失败

印：

- 固定资产 [`public/fengshui-assets/jinyuan-seal.png`](../../../public/fengshui-assets/jinyuan-seal.png)：原片复刻的朱文竖椭圆「锦垣」印
- 该 PNG 是 **RGBA**：仅红色印迹保留，印心和印外均透明；合成时必须保留 alpha，禁止铺红色实底、扁平化或重绘成其他印章
- 旋转 **2–6°**，以 **alpha 可见印迹**验收宽约 **106–112px**，不能拿含透明边的画布宽冒充
- 落在左列下方、略向两列间隙偏移，不压字；参考外框为画宽 `31.1%–41.5%`
- y 以**标题整体最大列**可见墨迹底部为基准，再下移约画高 `1%–2%`；不能按短列底部或固定画布底边定位
- 1080×1920 下印章可见左边约 `336–340px`；2026-09-04 放大版验收为 `x=338–448`、`y=最长列底+24px`，竖向位置随标题最大列实际底部联动

### 5. 字幕

- 字体：**宋体加粗 100px**（Noto Serif CJK SC Bold / `Noto Serif SC` Bold）
- 距底约画幅 **五分之一**
- **只有中文**；不加书名号《》
- 跟配音时间轴走（逐句/逐段对齐口播）

### 6. 本机成片编码

- 画幅 **1080×1920**（9:16）
- 静图始终静止；字幕跟配音
- x264（或等价）参数须含：`bframes=0:keyint=30:min-keyint=30:scenecut=0`
- 在配音任务结束且本机预检仍通过后，才以单任务运行 FFmpeg 导出 mp4

示例（按实际滤镜/字幕轨改；硬性是分辨率与 x264 参数）：

```bash
ffmpeg -y \
  -loop 1 -i still-1080x1920.jpg \
  -i voice.wav \
  -vf "scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920,…" \
  -c:v libx264 -pix_fmt yuv420p \
  -x264-params "bframes=0:keyint=30:min-keyint=30:scenecut=0" \
  -c:a aac -shortest \
  out-1080x1920.mp4
```

### 7. 交付

1. 成片上传（走仓内 OSS 惯例时可 `bash scripts/oss-upload.sh`，预览勿只丢裸链）。
2. 必须取得**绑定本次 MP4 的成片专属 HTTPS 深链**；该页面打开后应直接展示并可播放本次成片。
3. 交付前用无登录的新会话实际打开深链，核对：
   - 播放器请求的对象 key / URL 与本次上传结果一致；
   - 视频可起播、无 403，时长与本地成片一致；
   - 页面没有落回首页、历史帖子或上一条成片。
4. 对话框只发上述验收通过的实验室 HTTPS 深链，链接单独给人。官方形态：  
   `https://39.106.179.17.sslip.io/?tab=fengshui&v=<日期目录/文件名.mp4>&title=<中文标题>`  
   用 `fengshuiVideoPreviewPagesUrl()` 生成；**禁止**把裸根路径 `https://39.106.179.17.sslip.io/`、通用 `?tab=data`，或会被 SPA 吞掉的 `/previews/.../` 目录链当作成片交付。
5. **HTTP 200 只证明网页存在，不证明本次视频存在或可播放**。若当前前端没有成片播放器 / 专属路由，交付阶段就是阻塞：明确报告“成片已生成但预览发布未完成”，不得用根路径冒充完成。
6. **不要**往聊天塞视频附件；**不要**把 OSS 裸链当作唯一交付；**勿发 HTTP 裸 IP**。
