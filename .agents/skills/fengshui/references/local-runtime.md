# 本机声音克隆运行与门禁（老者）

风水竖版成片按 **CosyVoice > VoxCPM2 > VoxCPM 0.5** 选择本机可用引擎。优先使用已经安装且模型可读取的最高优先级引擎；三者都未安装时，按相同顺序评估机器资源并在独立环境安装第一个能安全完成 10 秒样本的最新兼容稳定版。禁止 MiniMax。

## 老者参考资产

- prompt 音频：仓内 `public/audio/150-20s.wav`
- 规格：PCM 16-bit、16 kHz、双声道、20 秒
- **克隆时使用该文件的 `0.00–16.78s` 完整语义段**；源文件保持不变，只在运行时裁出临时 prompt WAV。20 秒源文件末尾第二个分支被截断，禁止把未完整说出的句子写进 prompt 文本
- `0.00–16.78s` 精确参考文本：

  > 想知道自己去何处求财，给大家分享一个简单的小方法。记住自己月柱下面的那个字，如果是寅申巳亥，去外地求财。

参考音与这段文本必须成对传给现有 runner；不得用其他声线或自行改写参考文本替代。
`public/audio/150-20s.wav` 就是正式的老者克隆参考音，不再从外部仓库查找或下载 `laozhe-ref.wav`。

该文本来自 Whisper Medium 与 Large-v3 对同一音频的一致转写，并按风水术语把同音误识别恢复为「月柱 / 寅申巳亥 / 子午卯酉」；旧登记文本「内心深处对他人的真实评价……」与该文件无关，禁止再用。

首次使用或参考资产变更后，必须先用中文 ASR 核对音频与上述文本；领域专名允许依据双模型同音结果恢复正确汉字，但普通词仍须逐字一致。不能只凭文件名、哈希或时长推定内容一致。

## 引擎探测与选择

1. 依次检查 CosyVoice、VoxCPM2、VoxCPM 0.5 的 runner、版本和模型是否完整，做最小加载测试，不先跑全片。
2. 多个可用时只选顺序最前者。记录：引擎名、版本、模型、设备、参考音 SHA-256。
3. 三者均未安装时，再评估内存/显存/磁盘和现有负载。安装与模型加载必须在独立环境；一次只尝试一个引擎。
4. “机器能跑”以模型加载成功、10 秒真实样本完成、无 OOM / swap 持续增长且样本通过质量门禁为准，不能只看依赖安装成功。
5. 当前引擎连续两次质量失败后，清理其进程再尝试下一引擎；不得同时加载两个声音模型。

### 已验证的三级回退

- CosyVoice3：`Fun-CosyVoice3-0.5B-2512`，24kHz；本轮两次内容正确但停顿/语速未过
- VoxCPM2：`voxcpm==2.0.3`、架构 `voxcpm2`，48kHz；本轮两次内容正确，最佳稿标点停顿仍超限
- VoxCPM 0.5：官方 `openbmb/VoxCPM-0.5B`、revision `b2e656f7524303fdaf84591c75bbb87203d7c98d`、架构 `voxcpm`，16kHz；同一 `voxcpm==2.0.3` 按架构分流到 `VoxCPMModel`。它与 VoxCPM2 不是同一模型，调用 continuation API 时使用 `prompt_wav_path + prompt_text`
- 2026-09-04 当前机器的门禁通过样本由 VoxCPM 0.5 生成；这只是实测结果，后续新机器/新版本仍须从 CosyVoice 开始按优先级探测，不能永久跳过高优先级引擎

## 启动门槛

1. macOS 检查 `memory_pressure`；Linux 检查可用内存、swap 与 OOM 日志。出现 throttled pages、swap 持续增长或可回收内存不足时直接等待。
2. 与用户正在运行的 ASR、OCR、嵌入、其他 TTS、FFmpeg/Remotion、Blender 互斥；并行任务尚未让出安全窗口时等待。不暂停、杀掉或降级用户的现有任务。
3. 只运行一个合成单元；质量门禁结束且声音模型退出后，才运行 FFmpeg 编码。

## 音频质量门禁

每句保留目标文本、ASR 文本、字级时间戳和测量报告：

- 中文逐字一致：去标点后零错字、零漏字、零多字、零换序；语言必须是中文
- 句首/句尾静音 ≤300ms；非标点停顿 ≤350ms；标点停顿 ≤650ms；内部静音 >1s 直接失败
- 削波占比 ≤0.01%；SNR ≥25dB；无点击、爆音、底噪突变、嗡声、吞字、重复音节和语言幻觉
- 综合响度 -20 至 -14 LUFS；True Peak ≤-1dBTP
- 基频中位数建议为参考音的 0.75–1.25 倍，且不得持续低于 65Hz；检查 50/60Hz 工频和 60Hz 以下异常能量
- 中文语速建议 3–5 字/秒；ASR 字级覆盖 100%，不能提前 EOS

任何一项失败都不得上传试听或进入视频合成。文件可解码、音轨存在、响度接近参考都不代表发音正确。

### 点击 / 爆音审计与透明修复

1. `abs(diff)` 大跳变只作为候选，不能单独判定点击；低沉男声约 80–90Hz 的周期性声门脉冲也会产生大跳变。必须检查候选是否是极短孤立突刺、是否与前后局部 RMS / 频谱显著不连续，并与 F0 周期对照。
2. 门禁要求：孤立脉冲为 0；所有高幅候选均已解释为周期性声门或正常辅音，或已被透明修复。报告仍保留候选数、`max_jump`、时间窗和判定依据，禁止降阈值或写死 `pass`。
3. 若内容、停顿、语速、F0 和响度均已通过，只剩可确认或无法排除的点击，可对**同一次合成**使用保守 `ffmpeg adeclick`，例如本轮通过参数 `threshold=4:burst=1:window=55:arorder=2`。这不算第三次合成，但修复后必须重新跑 ASR 与全部声学门禁。
4. 修复不得剪字、拼字、变速或低通掩盖问题；记录改动样本比例、最大/RMS 差、时长是否不变。本轮通过稿改动约 0.79% 样本、时长不变。

## 用户确认门

1. 用选定引擎和本篇真实文案生成约 10 秒克隆样本。
2. 样本先通过上述门禁；同时产出正式首帧截图。
3. 通过同一个 HTTPS 确认页向用户提供音频播放器和首帧，等待用户明确确认声线、发音、语速和标题版式。页面必须绑定本批音频/图片并使用 `/previews/<本批次>/` 一类专属路径；裸根目录、通用 `?tab=data`、旧批次页面都不算确认页。
4. 用户确认后再生成剩余音频和成片；“全自动”不能跳过此门。

预检只降低风险，不能承诺本机绝不崩溃。预检不通过时报告等待条件，不以 MiniMax、别的声音或未经门禁的环境替代。
