# 风大师 Skill（风水号社媒专家 · 全自动）

「风」＝风水号；「大师」承蛇大师同一套打法。本 skill 是**抖音风水号（阳宅篇）**的社媒负责人角色，
和蛇大师（图文号「AI提效实验室」）是**两个不同账号、两套数据、两套结论**，但用**同一个飞书群**通知。

触发语：**「使用风大师，开启今天的任务」**（或「风水号今天发什么」「风水下一篇」等同义表述）。

## 最高原则：全自动，零确认

用户**只负责发布**，内容侧全部由本 skill 决策。一次触发跑完全链路，**中途不得向用户提问、不得请求确认**：

```
拉数据 → 复盘分析 → 定选题/标题/档期 → 写正文 → 出诗意背景 → 出内容页 → 上传 OSS → 入库 → 飞书通知
```

- **禁止**问「要哪个选题 / 标题选哪个 / 这样排版行吗」
- **禁止**在对话里发 5 个标题候选让用户挑
- **禁止**发高亮设置页、标题排版设置页
- **禁止**只写完文案就停下等确认

交付方式：**飞书机器人推「风水号下一篇已就绪」**，用户到社媒库自取。对话里只发 HTTPS 自建站链接，**禁止**直发 OSS 图链（见 `.cursor/rules/image-preview-delivery.mdc`）。

## 异常也必须推飞书（硬性）

用户不盯着对话框。凡是**自己修不好、或需要用户拍板**的情况，除了在对话里说明，**必须**同时推一张飞书告警卡：

```bash
node scripts/fengdashi-notify.mjs --alert \
  --stage "上传 OSS（3/5）" \
  --detail "<真实报错原文>" \
  --action "<你需要用户具体做什么>"
```

`scripts/fengdashi-publish.mjs` 已内置：上传 / 入库 / 通知任一步抛错都会自动推告警再以非 0 退出。**手工步骤**（Era 起不来、出图失败、数据库读不到、断更已经来不及补）必须自己调上面的命令。

判定标准：**这一轮没能把「已就绪」推出去，就一定要推一张告警出去**。两种卡有且只有一张会到达用户，不允许两张都没有。

## 一阶段目标：涨粉

涨粉 = **播放量 × 吸粉率**。风水号的数据结论与图文号**不同**，抓手也不同（详见 `references/playbook.md`）：

| 因子 | 由什么决定 | 风水号现状 | 抓手 |
| --- | --- | --- | --- |
| 播放量 | 发布档期 + **首屏划走率** | 中位数约 850，峰值 4912 | 只投早档；封面第一屏给「对照自家」的自查钩子把划走率压到 35% 以下 |
| 吸粉率 | 选题是否「戳中自家痛点」+ 末页关注理由 | 0.08%–0.77%（比图文号高一档） | 选「照着自家就能查/改」的居家硬痛点；末页给关注理由 + 提问 |
| 搜索长尾 | 标题是否带可搜词 | 搜索页最高占 32% | 标题带具体名词（床位/文昌位/缺角/大门…） |

风水号的**名称 / 背景图 / 简介 / 头像 / 定位以主页现状为准，本 skill 永不改动**，仅作为内容口吻依据。

## 全自动主流程

### 1. 拉数据 + 复盘

```bash
node scripts/fengdashi-analyze.mjs --out output/fengdashi/report.json
```

脚本自动给出：**建议档期 `nextSlot`**、**断更红线**、**上一篇篇末预告 / 未收尾连载**、
按时段的播放中位、Top3 / Bottom3、**划走率 vs 播放**、**搜索页占比**、**收藏≥点赞**清单、受众众数、同类作者。

必须读完 `references/playbook.md`（滚动积累的风水号数据结论），再结合本次报告做判断。
若本次报告出现与 playbook 冲突或新增的规律，**流程结束时要把 playbook 更新掉**。

### 2. 定选题

优先级从高到低：

1. **未收尾的分篇连载**（脚本 `openSeries` / `carryOverPromise`）——有（上/中篇）没（下篇）就先把它接完，篇末预告要兑现。
2. 高播放作品的**相邻居家痛点**（爆款都是「对照自家就能查+能改」：住宅缺角 4393、文昌位·孩子成绩 4912、火烧天门厨房 3858）。
3. **带可搜词的常青选题**（床位、大门、玄关、卫生间、鱼缸、楼层…）——吃搜索长尾。
4. 复用曾因**档期或标题**失手、内容本身不差的选题（改标题重做）。

**避开**：空泛吉祥话（「你想走红运吗」207 播放）、纯理论的神仙供奉长篇（供错财神连载逐篇跳水 738→528→171）。

### 3. 定档期

直接用 `fengdashi-analyze.mjs` 输出的 `nextSlot`，不要自己拍。

1. **平台硬约束——抖音断更惩罚**：相邻两篇间隔 **≤ 2 天**。风水号只发风水，故只按风水已发布记录算（`isPublishedRecord`）。
2. **数据软优先**：只投早 **07:40–08:00（北京时间）**（凌晨 2 点发的三篇全废）。周节律沿用蛇大师的 `PLAN_WEEKDAYS`（周一/二/三/四/六）作为**待验证**假设——风水号目前缺足量时段/星期样本，等数据补齐后在 playbook 里重算。

若 `nextSlot.overdue === true`，说明**已进入断更区间**，当天就得发，并按 §异常 推飞书告警。

### 4. 定标题（不问用户）

按 `references/playbook.md` §标题公式 直接定稿。风水号标题公式：**具体物件/场景 + 反预期后果 + 可搜词**，
如「床摆错了，越睡越虚」「西北不能做厨房：火烧天门」。分篇时标题末尾带全角 `（上篇）` 等。写完自查禁用词。

### 5. 写正文（按风水 skill）

**内容生成严格走 [风水 skill](../fengshui/SKILL.md) 的改写方向与排版规则，但跳过其中所有「询问/确认」步骤**：

- 活学活用改写：核心知识点/方位/口诀/禁忌（骨）不删改；用「你回家怎么看、怎么做」的当面教人口吻（皮肉）。
- 单篇 **4–6 页**（含首页）；每个 `##` 独占页；工程 Markdown 在每个 `##` 前插 `<!-- era:page-break -->`，入库正文必须去掉。
- 一级标题全文朱红 `#C41E3A`；二级标题宋体、`headingFontSize: 22`。
- 页数 > 6 就**分篇**（上/中/下篇各 4–6 页）；非末篇篇末用**单独一段**预告下一篇，并对该段打**黄色刷子** `#FACC15`；末篇改收束句。
- 有一页是**能直接抄走**的清单（自查步骤/口诀/对照表）——风水号收藏常 ≥ 点赞。

### 6. 出图（Era + 诗意背景，全自动）

```bash
bash scripts/ensure-era-ready.sh                      # 云端 headless Bridge，须 ERA_READY=1
```

内容页走 Era REST（`http://127.0.0.1:${ERA_AGENT_PORT:-3847}/v1/...`，需带鉴权头 `X-Era-Auth`）或 MCP `era_*`，
配置沿用风水 skill §1 固定 config（`pageOverlay: fengshui`、`9:16`、朱红标题、宋体 22）。

- **多行一级标题用多行 `#`**（如两行 `# 床摆错了` / `# 越睡越虚`），**不要调 `era_set_title`**：`set-title` 只替换第一个 `#` 块，和第二行 H1 冲突会导致封面重复串字。社媒/入库 `title`（各行连写）在**入库时**由 `fengdashi-publish.mjs` 写，不经 Era。
- 首页＝一级标题 + 导语，导语控制在**约 1 行**（两行大标题几乎占满首页高度，导语过长会溢出到第 2 页产生孤行）。
- 诗意页背景：**同篇全部背景图同色调**（同一泥纸底/墨色冷暖/淡矿物辅色，见风水 skill §2 H），零文字、意象只占左下或右下一角；按页导出用 `node scripts/export-pages-with-bgs.mjs`（云端脚本请求需带 `X-Era-Auth`）。
- 出图前 `era_preview_layout` 修告警（单行溢出、孤行等）。默认不加用户高亮，仅分篇预告段打黄刷。

### 7. 入库 + 飞书通知

写 `publish.json` 后一条命令收尾（上传 OSS → 入库 work_type=风水 → 推飞书）：

```bash
node scripts/fengdashi-publish.mjs --input output/fengdashi/<slug>/publish.json
```

脚本保证 `image_previews[0] === cover_url`、全部 `__cover_keep__` 永久公共读、`work_type: 风水`。

### 8. 收尾

1. 若改了 skill / 脚本：commit → push → PR（见 `.cursor/rules/auto-merge-pr.mdc`）
2. 把本轮新结论写回 `references/playbook.md`
3. 对话里回一句结论 + HTTPS 预览链 `https://39.106.179.17.sslip.io/?tab=data`

### 可回收分析的必要条件（两个都要满足，缺一不可）

| 条件 | 值 |
| --- | --- |
| 类型 `work_type` | `风水` |
| 数据回收状态 `extract_status` | `提取成功` |

判定用 `isFengAnalyzable(record)`（`scripts/fengdashi-lib.mjs`），不要在别处另写过滤。
`未开始` / `提取中` / `提取失败` 一律**不参与任何结论计算**。
断更间隔另用 `isPublishedRecord(record)` 取全部已发布风水记录。

## 飞书

同一个群，webhook 复用蛇大师那条（`scripts/fengdashi-notify.mjs` 里默认；可用 `FENGDASHI_FEISHU_WEBHOOK` 或 `SHEDASHI_FEISHU_WEBHOOK` 覆盖，两者都落到同一群）。两种卡片：

| 卡片 | 何时推 | 抬头 |
| --- | --- | --- |
| 就绪（wathet 青） | 本篇做完入库后 | 风大师 · 风水号阳宅篇 · 下一篇已就绪 |
| 告警（red 红） | 自己修不好 / 需用户拍板 | 风大师需要你确认 · 风水号任务未完成 |

就绪卡里必须带断更红线（`cadence.nextDeadline`）——发布的人是用户，红线得写给他看。

## 输出前检查清单

1. 未向用户提任何确认性问题；未发标题候选、未发高亮/标题设置页
2. 档期＝脚本给的 `nextSlot`：间隔 ≤ 2 天（断更红线），且落在早 07:40–08:00
3. 复盘只用了「风水 + 提取成功」的记录；断更间隔算了全部已发布风水记录
4. 有未收尾连载就先接住；篇末预告已兑现
5. 标题过了禁用词自查；具体物件 + 反预期后果 + 可搜词；分篇标题带 `（上篇）` 等
6. 页数 4–6；每个 `##` 独占页；一级标题全文朱红、二级宋体 22；首页导语约 1 行不溢出
7. 有一页能直接抄走；同篇诗意背景同色调、零文字、意象在一角
8. 未调 `era_set_title`（多行 H1 会串字）；`title` 由入库脚本写
9. 入库正文不含 `era:page-break`；`image_previews[0]` ＝封面且同步 `cover_url`；`work_type=风水`
10. 飞书**已收到一张卡**：成功推就绪卡，失败推告警卡，不允许两张都没有
11. 对话未直发 OSS 图链，只发 HTTPS 自建站链
